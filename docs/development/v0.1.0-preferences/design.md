# preferences

> 当前工作版本：v0.1.2

## 目标与范围

- 在主窗口设置页提供主题、采样间隔和网卡选择，并在重启后恢复已确认设置。
- 默认跟随系统主题、1 秒采样、自动选择一个主要联网接口；可选浅色/深色、1/2/5 秒和指定网卡。
- 开机启动纳入本次范围；悬浮窗、置顶及告警设置后置。任务栏验收在原任务栏功能记录。

## 方案

- v0.1.2：原“版本与升级”卡片接入 [app-update](../v0.1.2-app-update/design.md) 的真实更新状态、偏好与公告入口，替代仅有手动升级说明的旧方案。更新偏好单独原子保存，不阻塞采样或混入监控设置修订号。

- 卸载自启清理：复用平台计划任务脚本，检查 Pinmeter 命名范围与任务动作的规范化绝对路径，只删除指向当前卸载 EXE 的单一无参数启动任务，并重新读取确认已删除；其他安装或便携目录的任务保留。清理在卸载恢复命令的权限上下文内执行，失败中止卸载。同目录升级不删除注册。

- 2026-09-23 版本与升级说明：设置页展示来自工程清单的应用版本，以及构建时注入的源码提交/工作区状态和时间；侧栏复用同一版本来源。说明便携包保留完整目录、完全退出旧版后启动新版及迁移后重新设置自启；保留现有设置，不增加联网检查或自动更新。复用 Sakani Card 和正文规格，深浅截图与本轮主窗口验收共同记录。

- **保存不阻塞监控（2026-09-22）**：所有设置入口共用宿主串行门；核心先校验并准备变更，在监控状态锁外执行自启注册、原子写入和失败补偿，最后短暂持锁接纳结果。保存期间继续采样和推送旧的已确认配置；退出先禁止新操作，再等待已接纳保存完成，按最终偏好清理。原生任务栏设置和记住关闭选择复用此流程，不复制监控历史或覆盖期间收到的新样本。

- **开机自启（2026-09-18）**：设置页“启动”卡片复用 Sakani Switch，默认关闭，旧配置缺字段也为关闭；勾选或取消立即保存并注册/移除当前用户登录启动任务，恢复默认同时关闭。登录后正常显示主窗口，沿用单实例及窗口位置恢复。当前 Windows 需要管理员采集权限，因此采用当前用户 SID 的交互式、最高权限计划任务；不保存密码、不安装服务，不在无人登录时启动。手动启动仍遵循原 UAC 流程。[微软任务安全上下文](https://learn.microsoft.com/en-us/windows/win32/taskschd/security-contexts-for-running-tasks)
- 核心配置增加 `autostart`（默认 false），通过启动适配端口协调系统注册与配置保存；注册失败不提交配置，保存失败撤销本次注册并明确报告撤销失败。平台模块封装计划任务，宿主仅装配与协议转换；启动时只读取系统状态，不因旧偏好重新启用被系统禁用的任务。状态另行展示，不把已保存偏好当作实际生效证明。其他平台禁用此开关并解释尚不支持。
- 任务仅指向开启时的当前 EXE 及工作目录，不附带开发参数；路径以数据传递，包含空格、中文、引号或 PowerShell 特殊字符不能成为脚本。迁移运行目录后需在新位置重新关闭/开启；便携交付需保留整个目录。
- Sakani 来源为官方 Storybook 的 [Switch](https://main--6a5a658b3681fcc010430db5.chromatic.com/?path=/docs/forms-switch--docs)/Card/Alert 及 `@sakaniui/react` 0.3.1；HTML 仅作为布局参考。验证默认、选中、键盘焦点、保存中禁用及失败回滚的深浅主题截图。

- 2026-09-17 最新关闭规则由 [desktop-runtime](../v0.1.0-desktop-runtime/design.md) 维护：默认询问最小化或退出，记住的选择可在“窗口行为”重设，与任务栏显示开关独立，覆盖原启用任务栏后自动收起的规则。

- **任务栏设置（2026-09-17 已接入）**：复用现有版本化保存流程，增加启用、布局与显示项；功能初始关闭，启用后默认双行紧凑，下载/上传与 CPU/内存两组。所有开关、选择和恢复读数操作立即保存生效；关闭行为独立设置。期望启用与实际显示分开，保存失败不切换常驻行为，系统嵌入失败保留偏好并显示原因；没有可用恢复入口时不隐藏主窗口。详细契约、预览和验收集中在 [taskbar-display](../v0.1.0-taskbar-display/design.md)，本页已展示这些控件，浏览器演示不会实际嵌入系统任务栏。

- S3 使用版本化 JSON 保存偏好；同目录临时文件写入并同步后原子替换，保存失败不更新核心配置。损坏文件保留原件并显示启动诊断，后续修改设置可恢复配置。

- 遵循 [产品默认值与口径](../../design/product-design.md) 第 5、6 节和 [架构设置用例](../../architecture/overview.md) 第 5、6 节。
- [主窗口](../v0.1.0-main-window/design.md) 提供页面，ViewModel 在用户操作时立即携带 `expected_revision` 交给后端校验与原子保存。
- 设置页的控件、主题和保存反馈遵循 [产品设计第 5.4 节](../../design/product-design.md#54-视觉规范) 的 Sakani 标准，使用主窗口统一的基础控件；HTML 仅供布局。视觉整改与截图对照统一在 main-window 跟踪，已有保存逻辑验证不代表视觉达标。
- 核心持有已确认配置，platform 负责本地存储，host 跟踪实际应用状态；失败不显示为已生效，控件回到后端已确认值并显示可理解的原因。
- 等待原子保存回执期间禁用控件和恢复默认，防止重复写入；移除“应用”“放弃更改”。回执携带后端已保存设置，界面合并其版本；同一会话较旧采样回执不能覆盖新设置。失败恢复已确认值，用户可直接重新操作，不自动重试写入。恢复默认也立即保存。
- 网卡列表来自 [基础监控](../v0.1.0-basic-monitoring/design.md)，显示接口名称与状态。自动选择的实际接口可见；手动接口消失时显示不可用，不静默换卡。
- 采样间隔变更在安全边界生效；换网卡重建基线，历史不拼接旧设备曲线。配置损坏使用默认值并保留诊断线索。

## 验收

- 默认及旧配置不开启自启；开启/关闭/恢复默认对应系统任务变化，版本冲突不产生系统副作用，配置写入失败撤销注册。独立测试不遗留启动项；真实重启登录未测试时明确记录。

- 操作后无需额外按钮，各页面展示同一配置版本，重启能恢复；写入失败、版本冲突、接口消失均有明确反馈。
- 主题切换保持既定单位与数据口径，刷新间隔切换不产生重叠采集或重复订阅。
- 设置页只展示本版本已实现的能力，可用键盘完成操作，配置与日志写入系统应用目录。
- 设置页深浅主题及选中、禁用、保存中和错误反馈通过主窗口的 Sakani 对照验收。
