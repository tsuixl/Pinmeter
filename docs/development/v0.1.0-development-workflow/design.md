# development-workflow

> 当前工作版本：v0.1.0

## 目标与范围

- 维护可直接阅读的公开源码、开发约定及功能文档。
- 保留当前行为、技术依据、验证范围和未解决事项；清理本机信息、冗长过程记录与过时截图。
- 本次保留现有 GitHub 仓库和地址，准备一个不继承旧提交历史的公开基线，不新建远端仓库。

## 方案

- [AGENTS.md](../../../AGENTS.md)是规则入口，[开发约定](../README.md)维护功能目录、版本和提交流程。功能保持原 design.md 与 execution.md 两份文件。
- 普通参考项目集中在中英文 README 致谢；技术调研保留必要的公开来源，移植代码、库和字体的许可证、版权及修改告知原样保留。
- 执行记录只保留已实现内容、既有检查的范围及未完成任务。删除逐次交付日志、用户本机绝对路径、其他项目源码目录和过时构建标识。
- 公开文档仅保留 README 的总览、任务栏两张产品截图及 HTML 布局预览；历史测试截图和原始测量记录留在本地历史备份。后续 UI 修改仍按规则保存新的可复核证据。
- Sakani 是强制视觉与组件标准，HTML 仅提供页面结构参考。整理记录不扩大视觉、管理员或发行验收结论。
- 操作前备份完整 Git 历史并验证 bundle 可恢复。清理后使用 GitHub noreply 邮箱生成只有一个初始提交的本地分支，原分支和备份继续保留。
- 远端历史替换需在本地结果可检查后明确确认；不自动改变仓库可见性、创建发布标签或上传运行包。仅替换分支不能保证 GitHub 缓存、拉取请求或他人克隆中的旧对象消失。

## 验收

- 新公开分支只包含一个根提交，不携带旧日志、旧截图或原提交邮箱。
- 应用源码、锁文件、构建配置和必需的第三方声明内容不变，文档本地链接及工程检查通过。
- 中英文 README 保留最新总览和纯读数任务栏图片；设计文件不再依赖其他项目的本机目录。
- 当前已发现的构建、卸载、许可与运行验收缺口仍可查阅；清理记录不等于修复缺陷或发行就绪。
- 纯文档任务复核现有运行包即可，明确 EXE 未重新构建及正式发行必须重新绑定干净源码。
