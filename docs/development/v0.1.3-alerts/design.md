# alerts

> 当前工作版本：v0.1.3

## 目标与范围

- 提供用户主动开启的 CPU / 内存持续高占用提醒，两项默认关闭；只提示，不控制进程或网络。
- 规则包含阈值、持续时间、冷却和每日静默时段。借鉴 TrafficMonitor 的阈值提示，增加持续判定与冷却，避免瞬时尖峰和反复打扰。
- 本轮交付应用内提醒、最近 20 条会话记录及托盘悬停提示；点击可进入对应 CPU / 内存详情。记录退出后清空，规则随已有设置保存。
- 不发送系统弹窗、不请求通知权限。Tauri 官方通知在 Windows [只支持安装版](https://v2.tauri.app/plugin/notification/)，当前便携包不提供未经验证的系统通知开关。

## 方案

- `core/src/alerts.rs` 维护纯规则、连续时长、冷却和有界事件；后端唯一权威状态。仅复用监控核心已接纳的基础帧，无独立采样或网络访问。
- 只使用状态正常、0–100 范围的有限数值；重复/倒退样本、预热、失败、过期、采样代次变更和超出允许间隔的断档均不累计持续时间。重新取得有效样本后完整计算持续时长。
- 每次连续高占用最多提醒一次；下降后重新达到持续条件且冷却结束才再次提醒。静默期不生成事件，不在期满补发积压；静默结束后重新计时。墙钟仅标记事件，持续与冷却使用单调时钟。
- 静默区间使用宿主本地时间，支持跨午夜；起止相同无效。Windows 通过已有 `GetLocalTime` 获取，跟随系统时区。其他平台当前未实现本地时段适配，界面明确不可用；导入含静默配置时保守抑制提醒，不猜测时区。
- 配置复用已有版本校验和原子设置保存；提醒表单使用显式保存，编辑中的阈值和时段作为草稿，失败保留草稿并明确未生效。事件查看、确认及清除由薄命令调用核心，清除不会重置冷却。界面经 ViewModel 和统一客户端访问，不直接 invoke。
- 主窗口提示与设置页共用一个 5 秒读取缓存，仅当主窗口可见时请求；事件和规则仍以后端为准，旧读取不能覆盖保存回执，隐藏不保持提醒 IPC 轮询。浏览器演示不评估真实规则，仅 `alerts=events` 显式演示事件、`alerts=failed` 演示保存失败。
- 视觉复用 Sakani 0.3.1 的 [Alert](https://main--6a5a658b3681fcc010430db5.chromatic.com/?path=/story/composite-alert--all-colors)、[Switch](https://main--6a5a658b3681fcc010430db5.chromatic.com/?path=/docs/forms-switch--docs)、Input、Button 和 Card。HTML 预览仅作结构参考；深浅、禁用、保存失败、空记录与窄窗需分别验证。

## 验收

- 旧配置缺字段保持全关，阈值/时间边界被校验；保存失败不冒充生效，设置竞争显示冲突。
- 核心测试覆盖持续边界、每次高占用只提醒一次、冷却、恢复、失效、重复/倒退、断档、跨午夜静默、清除和 20 条上限。
- 应用内点击打开正确详情；托盘只在事件变化时更新提示，隐藏窗口不新增界面轮询，不弹窗抢焦点。
- 按仓库项目入口统一检查、构建和核对本轮完整运行包；真实高占用触发、原生托盘、重启配置及视觉未实测项如实保留。
