# diagnostics

> 当前工作版本：v0.1.3

## 目标与范围

- 设置页提供可预览的本地诊断快照，帮助核对版本、系统、采样状态、桌面入口和运行配置；用户主动导出至下载目录，不自动上传或发送反馈。
- 首期导出结构化 JSON，不收集完整日志、IP/网卡标识、用户名、安装路径、进程名单、规则目标或硬件序列号。采用字段白名单，不依靠对整包原始状态做字符串替换。

## 方案

- 2026-10-04 限时排障：用户明确开始后记录 30/60/120 秒，复用基础采样及唯一进程服务，窗口隐藏时仅在这段期限内继续按原频率采集进程；手动停止或到期立即撤销诊断需求，不影响页面已有需求。开始时可保留已有的一分钟基础回看，不推断开始前的责任进程。会话最多 61 个观测点及每点 CPU Top 3，不含路径、命令行或 IP，异常读数保留状态。记录仅存内存，用户预览并确认后单独导出 JSON；不混入原字段白名单诊断，不自动保存或上传。排障结束不执行任何系统/网络控制。

- `core/diagnostics.rs` 定义诊断模型并从权威监控状态投影；`platform/diagnostics.rs` 提供系统版本和有界、独占创建的文件导出；`host/diagnostics.rs` 负责主窗口授权、快照缓存与命令；前端 `features/diagnostics/` 按 View/ViewModel 组织，通过客户端调用。
- 仅主动打开时生成，后端最多缓存一份 64 KiB 报告。预览令牌绑定确切内容，导出同一份快照，过期令牌不能导出另一份内容。保存到系统下载目录，使用唯一文件名，不覆盖已有文件；显示真实结果。
- UI 复用 Sakani Card、Button、Modal、Alert；正文是可选择和滚动的文本。HTML 预览只用于布局。深浅、加载、失败、导出中和小窗口检查保留截图。

## 验收

- 预览与导出内容一致，文件为 UTF-8 JSON；重复文件名不覆盖，目录写入失败明确报告。
- 用带路径、地址、令牌及进程信息的源状态验证报告不包含这些原始字段；不将预热、失败和不支持显示为正常。
- 不增加后台采集或联网操作，不改变已确认配置；通过核心、平台、前端和契约检查，并与本轮 P1 统一构建交付。
