# app-network-ranking

> 当前工作版本：v0.1.3
>
> Windows 采集、核心汇总与网络页已实现；v0.1.3 接入应用历史归档与可选启动记录。部分实机与长期验收仍待完成，见执行记录；目录保持首建版本不变。

## 目标与范围

- v0.1.3：向[本地历史](../v0.1.3-local-history/design.md)提供一次性已接纳窗口增量，不另启采集器。网络页仍显示本次会话，停止再开始重置本次累计，但不清空已归档历史。可选择下次启动自动开始，默认关闭。

- 在网络详情的上下行曲线下增加应用排行，帮助用户找出当前主要使用网络的应用。
- Windows 首期提供应用名称与图标、上下行速率、按方向计算的占比、本次监控累计上传与下载，以及展开查看所属进程。
- 本功能只读，终止进程、逐 PID 历史和系统常驻服务不纳入；应用级历史由 local-history 维护。上下行限速与禁用/恢复网络在独立的[应用网络控制计划](../v0.1.0-app-network-control/design.md)维护，已通过排行应用行的右键/「⋯」入口接入；控制的规则与执行生命周期仍由该独立功能维护，真实效果待实机验收。
- macOS/Linux 保持契约与构建隔离，暂呈现“不支持应用网络排行”；基础监控继续可用，构建通过不代表采集支持。

## 方案

- 2026-10-04 说明收起：应用网络排行标题旁提供 Sakani 信息图标，排序方式、占比分母、统计口径、30 天历史和会话规则改为按需浮层；保留“全机应用流量 · 本次监控”、实际状态与计数。采集缺失/达到上限/操作失败只显示简短标记，详情浮层可查看完整原因。网络控制规则和恢复操作保持明确可见，不修改控制逻辑。与主窗口的网卡指标说明图标各自解释对应范围。
- 浮层复用共享 `InfoPopover`，触发器仅使用官方 ghost/sm 信息图标；标题为“应用流量说明”。正常/未监控的详细说明仅在浮层显示；累计缺失时即使当前采样正常，主状态仍标明“统计不完整”。操作失败、明细上限和固定目标缺失分别保留短 Badge，完整原因随说明按需查看。搜索、已记录/匹配计数、取消固定与历史入口合并在一行可换行工具区，排行及原网络控制操作保持可见。

### 页面与统计口径

- 2026-10-04 第 6 项：按现有稳定应用 ID 直达同一应用历史，返回恢复排序、展开、搜索、固定项和页面位置。名称/路径搜索覆盖当前本次监控的有界应用明细，固定一个目标置顶，不改变份额分母、计量和控制规则；离线/消失目标显示未在当前快照而不伪造零值。历史没有归档样本时明确提示。

- 沿用[产品设计](../../design/product-design.md)与[主窗口设计](../v0.1.0-main-window/design.md)。上方曲线仍统计选定单网卡；下方明确标注“全机应用流量 · 本次监控”，不随网卡选择切换范围，也不将应用合计与网卡读数相减或强行对齐。
- 默认按下载速率降序。名称、下载速度、上传速度分别提供可点击表头；首次选择名称按升序（中文拼音、英文与数字自然顺序），首次选择速率按降序，再次点击当前列切换升降序。当前列显示方向箭头，其余列显示双向排序提示，支持键盘操作与 `aria-sort`。
- 占比列跟随最近选中的下载/上传方向，按名称排序时保留原方向并明确列名。相同值按稳定应用标识排序，无效速率在升降序中均放最后；未归属与其他已归属汇总固定在应用之后。刷新保留排序、展开项和焦点，进程始终跟随所属应用。
- 下载与上传拆列，移除独立的排行切换按钮。窄窗口保留可点击表头并允许表格横向滚动，不缩小控件；排序是 ViewModel 的临时呈现状态，不修改后端计量或持久化设置。
- 占比 = 该应用在有效采样窗口中的该方向字节数 / 同窗口全部已归属应用该方向字节数。分母包含未显示在当前页的应用，不按可见行重算；无流量时显示“— / 暂无流量”。“已归属应用占比”不表示购买带宽利用率或选定网卡占比。
- 能计量但无法归属的流量单列“未归属”，不冒充应用或并入上述分母。事件丢失不等于可计量的未归属流量：丢失时标记统计不完整，暂停精确占比，累计值明确为已观测部分。
- 范围为全机可观测 TCP/UDP 收发，不等同于纯互联网流量；局域网、回环、代理和 VPN 的观察层次在原型中核对并写明。首期不承诺穿透代理/VPN 还原原应用，不把不同层次流量混加成物理带宽用量。
- 单位沿用十进制 KB/s、MB/s；累计量仅从本次开始采集时计数，不补算启用前流量。累计总数与瞬时速率分别保存，无效数据不填零。

### 应用归并

- 原始进程身份使用 PID 与创建时间，处理进程退出、短命进程和 PID 复用；不能仅凭 PID 沿用归属。
- 首期按规范化可执行文件完整路径归并同一程序的多个进程，不按显示名称合并。不能确认身份时保留独立进程或未归属状态，不猜测应用。
- 浏览器同一可执行文件的多个进程可归并；不同 helper 可执行文件、共享系统服务及软件套件不承诺自动合并。名称或图标读取失败使用可执行文件名与通用图标；可展示路径供辨认，不采集命令行或网络内容。
- 展开后的 PID 与状态文字位于应用名称右侧，使用 Sakani 间距变量增加子层级缩进；流量数值列保持与应用行对齐。
- 展开项显示已知进程与各自速率；状态文字为“本窗口有/无流量”，不将历史记录冒充存活进程。累计保留到本次监控结束。核心最多保留 128 个应用、512 个历史进程身份；超出应用上限的流量进入“其他已归属”，超出进程明细上限仍计入应用合计，显示限制说明。

### Windows 采集与权限

- 2026-09-18 退出残留修复：宿主在启动 helper 前生成独占的 ETW 名称和 GUID；退出发送 `shutdown`，只有停止 ETW、关闭消费者并等待回调结束后才返回 `shutdown_complete`。允许排空正在处理的采样响应，最多等待 8 秒，再回收异常 helper。宿主在 helper 结束后按本次名称与 GUID 查询、停止并确认会话消失，不扫描或停止其他实例的会话；停止错误不得冒充成功。`ControlTrace` 使用重新初始化的属性，失败保留句柄以便重试。
- 验收覆盖超过原 500ms 的清理、采样中退出、停止/重启、helper 无响应和异常退出回收；有管理员权限时核对真实 ETW 会话前后状态。此修复不将 ETW 残留直接认定为 VPN 故障根因，不修改 VPN、路由、代理或防火墙配置。
- 停止语义依据：[ControlTrace](https://learn.microsoft.com/en-us/windows/win32/api/evntrace/nf-evntrace-controltracew) 与 [CloseTrace](https://learn.microsoft.com/en-us/windows/win32/api/evntrace/nf-evntrace-closetrace)；分别处理会话停止与消费者关闭，区分已停止、仍在停止、清理失败与消费者排空。

- Windows x64 使用独立 C#/.NET Framework 辅助程序直接调用 ETW API，不增加采集库或网络驱动。独立命名与 GUID 的 SYSTEM_LOGGER 实时会话只开启 NETWORK_TCPIP，消费版本 2 的 IPv4/IPv6 Send/Recv 事件，不叠加 Retransmit/Copy；负载 PID 与字节数用于归属。现有 `GetIfTable2` 继续负责基础网络曲线。其他事件版本计入解码缺失，不能按正常零流量处理。
- 来源依据（2026-09-16 已查阅并完成部分本机实测）：[TCP 事件](https://learn.microsoft.com/en-us/windows/win32/etw/tcpip)、[UDP 事件](https://learn.microsoft.com/en-us/windows/win32/etw/udpip)、[StartTrace 权限与资源约束](https://learn.microsoft.com/en-us/windows/win32/api/evntrace/nf-evntrace-starttracew)。分工参照 [Windows 调研](../../research/windows-monitoring.md)。
- Windows 11 本机已跑通 ETW；60 秒受控 IPv4 TCP/UDP 回环传输的累计字节与收发端一致。本机 IPv6 TCP 回环返回 EACCES，UDP IPv6 能观察发送但接收端为零；不声明 IPv6 双向精度通过。代理/VPN 还原与重传场景仍单列限制，详见执行记录。
- 进程路径与创建时间在窗口汇总时通过只读系统 API 获取，并检查创建时间不晚于最早事件时间；已退出、路径不可读或 PID 复用边界无法确认的流量进入未归属。首期不追溯短命进程身份，不宣称完整应用归属率。辅助程序每窗口最多累计 4096 个 PID、输出 512 条进程明细，超过明细上限的已识别流量进入其他已归属。
- 图标从已确认路径只读提取 16px PNG，缓存最多 128 项、单项最多 4096 字节；失败回退通用图标。ETW 申请 64 KiB × 16–64 个缓冲区，系统可能按 CPU 数量调高；缓冲每秒刷新。窗口按收到事件计量，包含 ETW 缓冲延迟，瞬时读数不承诺与网卡严格对齐。
- Windows 权限由 [desktop-runtime](../v0.1.0-desktop-runtime/design.md) 在启动时统一取得。点击“开始监控”直接启动继承权限的只读 helper，不再弹 UAC；切页和最小化保留会话，明确停止才释放 ETW，helper 空闲等待，再次开始建立新会话和累计。异常退出后重新开始仍继承宿主权限，退出应用清理 helper，不安装常驻服务。
- helper 响应超时 5 秒，失败保留具体状态，不按采集功能请求授权。命令仅限 sample/stop，平台结果标注会话代次，迟到样本不能进入新会话。
- 只保留采集与身份归属所需元数据，不采集数据包内容、域名浏览记录，不保存原始事件日志。辅助进程只接受受限的启动、停止和读取请求，生产路径使用继承的标准输入输出，仅接受父进程请求并限制消息大小；独立探针的显式提权模式仍校验管道连接方，不扩大温度 helper 的职责。

### 生命周期与分层

- 连续监控：开始后切页、托盘及界面重连保留同一会话；明确停止、采集失败或应用退出结束采集。默认关闭，可选择下次启动自动记录。应用分钟历史独立保存，不增加采集源；本次累计与跨重启历史分别展示。窗口隐藏停止推送和绘图。更新失败后重建采集器时切换代次、接纳新序号，保留已有观测累计并标记间断，避免旧序号导致采集无法恢复。

- 默认关闭按应用采集。用户在网络页启动后进行本次连续监控，生命周期由后端请求状态管理，不由页面挂载、订阅或可见性管理。明确停止时释放 ETW、保留累计供查看，退出时清理 helper；再次开始建立新会话和累计基线，页面明确提示。基础网卡采集仍遵循原生命周期。
- 休眠恢复、采集器重连和事件丢失后建立新的速率基线，不跨空档计算尖峰；累计量保留缺失标识，不把空档当作零流量。主进程异常退出时，辅助进程通过父进程存活检查与退出清理停止自身会话，不关闭其他程序的会话。
- 遵循[技术架构](../../architecture/overview.md)：`core` 持有应用身份、字节汇总、速率、占比、会话及有效性；`platform` 负责 ETW、进程元数据与权限隔离，输出项目类型；`host` 只装配执行器、检查调用者并转换协议；ViewModel 经统一客户端调用用例。
- 事件消费与基础采样隔离，使用有界缓冲；平台汇总成带单调窗口时间、会话代次和丢失状态的项目观测后交给核心。排行按既有 1/2/5 秒间隔发布快照，调低界面刷新率不能冒充降低事件采集成本。
- 复用现有快照与订阅，排行不复制进基础五分钟历史。区分未启用、授权中、权限不足、预热、正常、统计不完整、失败、过期和不支持；旧会话迟到数据不得覆盖新会话，读取缓存不推进有效时间。64 位计数沿用十进制字符串协议。
- 代码归属：前端 `features/app-network/`；规则 `core/src/app_network.rs`；适配器 `platform/src/app_network.rs` 与辅助程序 `platform/network/`；契约放 `host`。`tools/build-network.ps1` 使用系统 .NET Framework x64 编译器构建，`desktop.mjs` 接入 Windows 构建与资源打包；产物与原始验证日志在被忽略的 `backend/target/`。

## 验收

- 能定位主要下载和上传应用，正确归并同路径多进程；方向排序与占比分母正确，展开进程不改变应用合计；已知应用、未归属、零流量与统计不完整可区分。
- 用已知进程的受控传输覆盖 TCP/UDP、IPv4/IPv6、多连接、双向流量、已存在连接、退出与 PID 复用；每个适用场景至少对齐 60 秒窗口，结合收发端计量核对事件字节语义，不以网卡总数或另一 ETW 展示工具单独证明精度。
- 单独验证代理/VPN、局域网与回环的归属限制。原型阶段冻结环境、参考方法、数值容差、缓存上限与额外 CPU/内存预算；未冻结或不通过时，不标记采集验收完成。
- 检查拒绝/取消授权、采集器崩溃、丢事件、过期、休眠、最小化、切页、重启监控与退出；不展示伪零值、旧会话数据或残留进程，失败不阻断基础监控。
- 发布构建分别测量基础模式与排行开启时的总体开销，包含 helper 和 WebView；覆盖空闲、高吞吐和大量短连接，按产品要求完成长时稳定性检查。
- 通过适用核心测试、前端类型/构建与平台构建检查；Windows 实机结果和其他平台未支持状态分别记录。保存 Sakani 深浅主题、排序/展开、键盘焦点、异常与窄窗截图，构建通过不替代视觉验收。
