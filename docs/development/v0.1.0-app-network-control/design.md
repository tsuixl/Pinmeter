# app-network-control

> 当前工作版本：v0.1.0
>
> 2026-09-17：按已确认的右键/「⋯」菜单和限速弹窗实现 Windows 控制链路。代码与演示交互已接入；重新授权后完成基础下载限速、新连接禁用与解除后的下载恢复实测。上传、多进程、已有连接及其他场景和完整发行验收仍未完成，详见执行记录。

## 目标与范围

- 在网络详情中，为单个应用设置下载上限、上传上限、禁用网络、恢复网络和清除限制。Windows x64 先实现，macOS/Linux 仅保持契约与构建隔离，明确显示不支持。
- 与[只读应用排行](../v0.1.0-app-network-ranking/design.md)独立维护：排行负责观察，控制规则不依赖排行是否开启，也不随切页、最小化或停止监控失效。
- 首期按已确认的程序完整路径管理，同一路径的多个进程共享每个方向的限速额度；同名不同路径分别处理。目标应用重启后规则仍可匹配，不以 PID 作为持久身份。
- 不包括结束进程、按域名控制、定时规则、流量配额、自研内核驱动、开机启动或常驻 Pinmeter 服务。不同 helper 程序和软件套件不自动合并；系统共享宿主、未知身份及汇总行首期不提供控制。

## 方案

- 2026-09-23 常驻内存整改：旧版空规则 helper 实测约 723 MiB 私有工作集；独立只读重复防火墙清单查询后，100 次枚举在完整 GC 后仍保留约 138 MB 托管内存，定位到动态 COM 枚举路径。将策略集合及规则访问改为固定 `INetFwPolicy2` / `INetFwRule` 只读 IDispatch 接口，及时释放枚举对象；不删除诊断、不停用网络控制、不靠周期 GC 掩盖增长。GUID、DISPID 和类型依据 [微软接口文档](https://learn.microsoft.com/en-us/windows/win32/api/netfw/nn-netfw-inetfwrule)及 [Windows SDK IDL](https://github.com/microsoft/win32metadata/blob/main/generation/WinSDK/RecompiledIdlHeaders/um/netfw.idl)。只读回归记录同机修复前后内存和 helper 哈希，真实规则读写仍由独立管理员验证覆盖。
- 恢复入口按平台支持和连接状态判断，不因 helper 暂时不可用或规则为空禁用“解除全部”；普通设置仍要求能力可用。快照分别传递 `supported` 与运行能力，避免将非 Windows 的不支持误报为故障。

- 2026-09-23 后续可靠性验收：使用本次指定运行包的 helper，在独立安装身份和复制的探针程序上实测已有连接、新连接禁用、解除恢复、helper 退出保留与重启解除；不操作用户程序或 VPN。验证脚本显式接受产物和输出目录，检查复制来源哈希，保留清理回读证据。

### 解除失败与空规则退出核对（2026-09-23）

- 空配置不代表系统没有残留。Windows 退出解除始终调用控制适配器核对；启动或重建 helper 失败时保留窗口并允许重试，不能因规则列表为空或旧报告不可用而宣告已解除。未实现控制的平台且无配置时仍允许正常退出。
- WFP 与防火墙清理分别执行、分别回读；任一路径失败不跳过另一条恢复路径。清理错误和无法读取的状态不能记作零条，仅两种系统规则都确认清空时返回成功；保留失败原因用于重试和本地诊断。
- 核心解除用例要求可用的实际回执，即使配置为空也拒绝不可用报告；继续先保存停用意图，清理失败后不自动重新启用。
- 在原核心/宿主测试与平台 helper 自检中注入失败，覆盖空配置、helper 启动失败与重试、单侧清理/回读失败及规则残留。不创建真实测试阻断，不操作 VPN 或现有实例；VPN 根因及管理员实际传输验证继续独立记录，不能由这些回归代替。

### VPN 偶发断联诊断（2026-09-18）

- 用户报告未操作限速时 VPN 断联，正常退出 Pinmeter 后恢复，重新开启排行未复现；根因未确定。保留限速、禁用与现有退出语义，不以关闭核心功能代替修复，不自动操作 VPN 或创建测试阻断。
- 在原平台 helper 增加本地有界诊断：记录进程/安装身份、收到的控制意图、引擎创建与释放、收发计数及最近进度、异常、实际系统规则和清理的具体对象。空规则也独立核对本安装 COM/WFP 规则，读取失败明确记录 unknown/error，不能记成零。
- 系统规则采样在独立后台线程低频执行，不阻塞控制协议与包处理；日志写入采用有界队列和后台落盘，失败不改变网络控制结果。不记录包内容、远端地址、访问域名或 VPN 凭据；应用路径仅作为本地规则归属证据。
- 宿主收到解除成功后可能立即结束 helper；清理返回前最多等待 250 ms 刷新已有日志，超时仍按真实清理结果返回，不能阻止网络恢复。强杀、断电和磁盘故障下最后记录仍可能缺失，不能将缺少事件当作动作未发生。
- 日志保存于当前用户 LocalAppData/io.pinmeter.desktop/diagnostics/network-control，每次 helper 运行独立文件，单文件限额并限制历史数量；目录不可写时明确回报诊断不可用。日志不上传，不进入运行包或 Git。诊断计数不参与监控指标或限速决策。
- 验收：无有效规则时引擎从未打开；空规则仍能记录实际规则或权限错误；shutdown/EOF 释放与日志完成；日志不可写、队列满、文件轮转不改变协议结果。已有控制自检保持通过。真实 VPN 故障、管理员控制场景及长期性能未复现/未执行时保持未验证。

### 操作与规则

| 操作                | 计划行为                                                                               |
| ------------------- | -------------------------------------------------------------------------------------- |
| 下载限速 / 上传限速 | 两个方向独立设置；每个方向可选“不限制”或正数上限，十进制 KB/s、MB/s，与排行一致        |
| 禁用网络            | 阻止该程序入站与出站网络通信，保留原限速值，不结束应用                                 |
| 恢复网络            | 解除 Pinmeter 为该程序创建的禁用规则，恢复已保存的限速设置；其他软件的阻止规则保持原样 |
| 清除限制            | 删除该程序的限速设置与 Pinmeter 禁用规则，成功后显示“未设置限制”                       |

- 禁用优先于限速；禁止用 `0 KB/s` 同时表示“不限制”和“断网”。负数、非有限数、换算溢出及超出输入范围的值不能提交。当前输入边界为 16 KB/s 至 1000 MB/s；这只是参数与队列保护范围，不代表吞吐精度已验证，实机容差仍待冻结。
- 应用行支持右键菜单与「⋯」按钮打开同一个菜单：设置限速…、禁用/恢复网络、清除所有限制；设置限速打开独立弹窗，同时编辑两个方向，取消不写入、保存后等待回读。禁用/恢复直接执行并展示处理中状态。应用行提供“网络控制”入口，显示下载上限、上传上限及禁用状态；PID 子行保留右缩进，仅展示继承的应用规则。保留现有名称/速率表头排序、展开状态和数值列对齐。
- 网络页提供“已配置规则”列表，即使排行停止、应用退出或无流量，仍能修改、恢复或清除限制；打开编辑界面后冻结目标身份，不能因排序刷新而操作到另一应用。
- 分开呈现“正在应用、已生效、部分生效、失败、能力不可用”；只有平台回读确认后才显示生效。无流量不等于已断网，保存设置不等于系统规则生效。恢复操作仅声明已解除 Pinmeter 的限制，不承诺目标应用自动重连。
- 沿用启动时统一取得的权限，不按应用或每次操作重复弹 UAC。未获得权限时显示能力不可用与原因。

- Windows [QoS 限速](https://learn.microsoft.com/en-us/windows-server/networking/technologies/qos/qos-policy-manage)针对出站，不能单独满足双向目标。
- [WinDivert 网络层](https://reqrypt.org/windivert-doc.html#divert_layers)能拦截数据包但不含 PID；结合 FLOW 事件与系统 TCP/UDP 连接表处理已存在连接、IPv4/IPv6、短连接和 PID 复用。无法可靠归属时放行并报告能力限制，不猜测归属；该路径不能作为严格防火墙的替代。
- 限速以应用路径与方向为共享预算，不能给每个 PID 各发一份完整额度。发送调度与包捕获分离；队列设包数、字节数、等待时间及全局上限，验证低速大包、公平性、顺序、突发和取消后的排空行为。
- 入站限速控制本机交付速度，不能承诺减少已经到达网卡的流量；TCP 与 UDP 的效果分别验证，不将丢包直接等同于稳定限速。
- 禁用规则覆盖指定程序的两个方向和全部网络配置文件；能力探测包含防火墙服务、当前配置文件与本地策略是否允许生效。服务关闭、组策略覆盖、规则被外部修改时，不能仅凭规则存在显示“已禁用”。
- 代理/VPN、回环和委托其他进程联网单列验证；普通路径规则不承诺封锁软件套件及所有间接通信。若首期无法可靠覆盖某场景，界面说明覆盖范围，不展示“完全断网”。

### 退出解除与规则停用（2026-09-17）

- 统一设置新增“退出 Pinmeter 时解除所有网络限制”，默认开启；旧设置缺失该字段按开启迁移。正常退出先停用规则、保留应用/原限速/禁用意图，清理本安装的系统限制并核对成功后退出；下次启动不自动启用。最小化、切页不解除。
- 规则新增 enabled，持久化格式升至 v2，v1 迁移保留旧规则启用状态；仅显式“启用已保存规则”才重新应用已停用规则。已配置列表展示保存值和“未启用”，支持启用、停用、删除及“解除全部限制”，不新建配置历史系统。
- 偏好关闭时，退出停止限速、保留网络禁用和原启用状态；存在禁用时给出退出确认。清理失败留在窗口，可重试或返回；不虚报已解除。首次实现只保证正常退出，强杀/断电仍可能残留，下次启动按持久化意图核对。
- 用户启用意图与实际执行分开：先保存停用意图再移除系统规则；失败显示“解除失败”及实际状态，不能仅凭 enabled=false 显示已恢复。全部退出入口共用后端退出流程，退出期间串行拒绝新规则/设置操作。
- 共用设置存储承载退出偏好，core 承载规则停用用例，platform 负责清理与回读，host 组织串行任务和窗口退出；ViewModel 通过客户端接收退出状态，View 只呈现 Sakani Switch/Modal/Menu/Button。新增退出桥接放 host/src/exit.rs，回归跟随现有功能测试。
- UI 继续以 Sakani 0.3.1 [Switch](https://main--6a5a658b3681fcc010430db5.chromatic.com/?path=/story/forms-switch--with-label) / Modal 为视觉依据；HTML 预览仅定义结构。验收覆盖默认/关闭偏好、旧配置迁移、停用后重启、重新启用原值、清理/存储失败、重复退出、深浅主题及窄窗。

### 生命周期与失败处理

代码按以下生命周期实现；基础下载限速及新连接禁用/恢复已有真实传输证据，其他场景仍待验证，不能以配置回读替代传输测试。

| 场景                    | 限速                                             | 禁用网络                                                           |
| ----------------------- | ------------------------------------------------ | ------------------------------------------------------------------ |
| 切页、最小化、停止排行  | 继续执行                                         | 继续生效                                                           |
| 目标应用退出 / 重启     | 保存规则，按同路径重新匹配                       | 系统规则保持                                                       |
| Pinmeter 正常退出       | 停止限速，保存设置；默认将规则停用 | 默认解除禁用；关闭退出解除偏好时，经提醒后保留 |
| Pinmeter 下次启动       | 仅重新应用 enabled=true 的限速 | 依启用状态核对禁用/解除，停用规则不重新启用 |
| 限速进程崩溃 / 驱动失败 | 停止拦截，报告限速失效，不伪装为仍受限           | 已确认的系统禁用规则保持；不能自动撤销                             |
| 卸载 Pinmeter           | 停止引擎并清理自身资源                           | 清理可确认属于本安装的规则，保留用户和其他软件规则；失败须明确报告 |

- 防火墙规则使用稳定的安装归属标识、应用规则 ID 和方向标识，保存操作记录并回读实际结果；不能按应用名称、路径相似或模糊前缀批量删除。机器级效果在界面说明，同一路径的其他用户进程也可能受到影响。
- 两方向规则的建立、解除并非事务：一侧失败时尝试恢复操作前状态；补偿也失败时保留实际状态与重试入口。启动时核对未完成操作，配置损坏不能触发清空系统规则。
- 禁用成功前暂停并清理该应用待发送队列，避免旧队列继续发送；恢复时先准备原限速配置，再解除禁用。引擎不可用时允许解除禁用，但必须显示“网络禁用已解除，限速未生效”。
- 应用移动/升级导致路径变化时，旧规则显示“路径不可用”，仍可清除；不自动将规则迁移到同名文件。禁止操作 Pinmeter 自身及其控制辅助程序，避免失去恢复入口。
- 恢复网络只移除本功能规则；目标程序可能需要重试或重新建立连接。已有连接的停止延迟、解除后的恢复行为必须实测，不能靠 API 返回成功推断。

### 分层与代码归属

- 遵循[架构](../../architecture/overview.md)与[Windows 调研](../../research/windows-monitoring.md)。`core/src/app_network_control.rs` 保存目标身份、限速配置、规则修订号、期望状态与实际结果；定义限速/防火墙能力端口，不依赖系统或 Tauri 类型。
- `platform/src/app_network_control.rs` 封装 Windows 防火墙、连接归属、WinDivert 与生命周期；实现采用独立 C#/.NET Framework 辅助程序，源文件归入 `platform/network-control/`，复用现有 Windows helper 构建和权限继承机制，不新增运行时安装要求或 Cargo 工作区。Rust 平台适配管理其受限协议；Throttle 用作算法与归属设计参考，不移植其 GUI。限速辅助程序与只读 ETW helper 分离，继承宿主权限，父进程退出时停止。
- `host` 装配执行器与薄命令，复用契约生成和既有快照/订阅；请求仅携带受控目标 ID、规则修订号与合法参数。辅助进程校验实际父进程、限制消息大小并拒绝系统目录和本安装目录目标；仅使用继承的 stdin/stdout，不接受 shell 命令。
- 前端新增 `features/app-network-control/`，从既有排行入口调用；View 经 ViewModel 和统一客户端消费后端状态。宿主用单工作线程调用核心规则用例，串行处理规则更新，拒绝过期修订号与迟到响应；平台保留执行副本，不产生第二份权威配置。
- 网卡曲线与应用排行仍使用原指标来源；WinDivert 调度计数仅作控制诊断，不与 ETW 相加。仅在存在有效限速规则时启动包处理，不记录、解密或持久化数据包内容；内存中短暂持有原始包仅用于调度和重注入。
- Windows 依赖条件编译隔离。构建/打包工具归入 `tools/`，驱动发行资源归属平台模块，生成物与日志留在已忽略的 `src/backend/target/`；移植代码保留来源、版本、许可证及修改说明。

### 本机代理阻断修复（2026-09-17，隔离管理员测试通过）

- 用户实测 Chrome 禁用后仍能联网。只读核对发现 Chrome 路径与已启用的双向规则一致，但连接集中到系统代理 127.0.0.1:10808；原有直连验证没有覆盖这段本机通信。
- 在原 C# 平台辅助程序中补充 Windows WFP 的 ALE 应用路径阻断，覆盖 IPv4/IPv6 的连接与接收入站层，不依赖修改代理设置、终止 Chrome 或阻断共享代理进程。原系统防火墙规则保留；全部阻断项回读成功才显示已禁用，否则报告部分生效。依据微软 [ALE 分层](https://learn.microsoft.com/en-us/windows/win32/fwp/ale-layers)与[策略变更重授权](https://learn.microsoft.com/en-us/windows/win32/fwp/ale-re-authorization)，仍需用实际传输确认断流和恢复。
- WFP 采用本安装独立持久子层与稳定过滤器身份，四层更新使用系统事务；过滤器直接归属子层，不绑定需要常驻服务的 provider。持久规则不会随 helper 退出自行消失；正常退出按全局偏好主动解除，恢复、清除与卸载只删除精确归属于本安装的过滤器，并适配旧版仅有防火墙规则的配置。新增文件归入 platform/network-control/，不增加服务或 crate。
- `tools/check-network-block.cjs` 将 helper 与 curl 复制到独立临时目录，使用唯一安装归属；先验证本机/代理可用，再检查新连接、已有流量、其他程序不受影响、退出后的阻断、恢复和清理。通过后才更新用户正在运行目录中的辅助程序。其余代理、协议和系统重启场景仍按实际结果记录。
- 管理员首轮测试发现子层回读与清理误报冲突。子层归属核对稳定身份、名称、描述、持久属性和 provider，不把请求的权重当作身份：微软[安装 provider 示例](https://learn.microsoft.com/en-us/windows/win32/fwp/installing-a-provider)说明 BFE 可以分配邻近可用权重。测试支持显式指定旧测试目录，先清理并复查该隔离安装的遗留规则，再重新测试；不扩大到用户安装。
- 重测已验证已有回环流断开、新建本机 HTTP 代理连接失败、其他程序不受影响、helper 退出后阻断保留、解除后恢复及零残留清理；可运行目录已换入通过测试的 helper。用户已反馈真实 Chrome 禁用测试正常；已有代理长连接、UDP/IPv6 与其他代理方式仍未验收，不据此宣称所有场景完全断网。

### 当前实现边界

- 配置最多 128 个路径，先原子保存期望状态再操作系统；失败保留恢复记录。修订号拒绝旧菜单/弹窗覆盖新设置。配置损坏保留原文件，不清空系统规则；序列化后超过 240 KB 的设置拒绝保存，避免写出下次无法读取的文件。
- 限速以 IP 包字节（含头部）为预算，排行保持原 ETW 统计口径；两者不保证数值完全相等。按路径与方向共享调度时间，FLOW 事件补充连接表归属；连接表每 250ms 刷新，发送队列每 2ms 调度。每方向最多 1024 包/1 MiB，全局最多 16 MiB，最长排队 5 秒，超限丢包；修改单条规则不会释放其他应用的队列。包归属不明确、回环、分片等不保证限速。
- 防火墙规则归属由安装目录散列、应用路径散列和方向组成，并核对描述、路径与方向；只删除精确匹配本安装的规则。平台每 2 秒回读；规则篡改、服务/策略异常或引擎退出显示失败/部分生效。正常卸载先停主程序，再清理并复查；失败时中止卸载并保留恢复程序。同目录升级保留系统禁用规则，等待新版读取保存的设置；跨安装目录迁移、升级与卸载真实执行尚未验证。
- `tools/build-network-control.ps1` 编译 Windows x64 的 .NET Framework helper，验证官方发行包、源码包哈希与驱动签名，并执行无需提权的调度/解析自检。`--inspect-platform` 只读检查防火墙能力及规则，`--verify-clean` 以管理员权限只读核对两种规则残留；`--cleanup` 在管理员权限下仅清理本安装的两种规则与 WFP 子层。卸载使用 `--cleanup-request` 继承或一次申请权限，将实际清理和回读结果的退出码返回 NSIS；取消或失败中止卸载。

## 验收

- 先完成 Windows 原型：同程序多进程共享上限、不同路径不串规则；上传/下载分别限速，另一方向仍可正常通信。冻结吞吐测量口径、预热时长、至少 60 秒稳态窗口、精度容差、突发窗口及 CPU/内存预算后再判断通过。
- 禁用测试同时使用已有连接和新连接，覆盖 TCP/UDP、IPv4/IPv6、互联网/局域网及配置文件切换；远端收发计量确认阻止与恢复，不能用排行零流量证明断网。记录回环、代理/VPN 的可控范围。
- 检查限速→禁用→恢复、清除限制、连续快速编辑、应用退出与 PID 复用；规则未生效或部分生效不得显示成功。包队列中的旧数据不能绕过新禁用状态。
- 验证切页、最小化、停止排行、主程序退出/崩溃、重启、休眠、网卡重连及引擎故障；与上述生命周期一致，无孤儿限速进程。驱动缺失或受阻不影响只读监控与独立恢复网络入口。
- 验证两方向写入/删除部分失败、配置损坏、外部修改规则、防火墙关闭/策略覆盖、其他软件既有规则、升级与卸载；只能操作本安装拥有的规则，异常结果可恢复。
- 通过适用 Rust 格式/测试/clippy、协议生成、前端类型/构建、Windows 打包及其他平台隔离检查；完成 Sakani 对照、原生 DPI 与长时间性能验证。未测环境和原型失败项不得标为支持。
